# Prompt ตรวจทาน: สถานที่รับคืนและค่าส่งแยกขา

สถานะ 25/10/2026: **แผนเท่านั้น ยังไม่อนุญาตให้นำงานนี้ขึ้น production** งานวันที่บนการ์ดรูปและขั้นตรวจรูปงานรับคืนแยกไปดำเนินการแล้ว จึงไม่อยู่ใน prompt นี้

## เป้าหมาย

พัฒนาเว็บจอง เว็บคำนวณค่าเช่า/ค่าส่ง Bot, Console Pending, Booking, Delivery App, คิวเช่าของฉัน, LINE, อีเมล และสัญญา ทั้งภาษาไทยและอังกฤษ ให้รับคืนคนละสถานที่กับจุดส่งและคิดค่าส่งแยกขาได้ โดยไม่ทำให้การจอง/ชำระ/เรียกรถเดิมสะดุด

## พฤติกรรมที่ต้องการ

1. หน้าเช่าและหน้าคำนวณมีช่องติ๊ก “สถานที่รับคืนต่างจากสถานที่ส่ง” เมื่อไม่ติ๊ก จุดรับคืนตามจุดส่งอัตโนมัติ เมื่อติ๊กมีช่องค้นหาสถานที่, ใช้ตำแหน่งปัจจุบัน และปักหมุดเหมือนจุดส่ง หน้าเช่ามีโน้ตรับคืน (ถ้ามี); หน้าคำนวณไม่มีโน้ต
2. สร้างราคา Lalamove สองขา: ร้าน→จุดส่ง และจุดรับคืน→ร้าน แต่ละขาใช้ประเภทรถและค่า priority ตามกติกาปัจจุบันของจังหวัด/โหลดขานั้น รวมสองขาแล้วหักส่วนลดค่าส่งที่ร้านออก **ครั้งเดียว** เก็บพิกัด, คำขอ, quotation ID, ราคาพื้นฐาน, priority, ยอดแต่ละขา, ส่วนลด และวันหมดอายุของ quote ทั้งคู่ใน snapshot ที่ตรวจความถูกต้องได้
3. ส่งจุดรับคืนไป `Return Location` ใน Booking/Delivery App และไปงานรถรับคืนจริง โน้ตรับคืนต้องถึงคนขับรับคืนโดยไม่ทับโน้ตจัดส่ง แสดงจุดทั้งสองและยอดที่ถูกต้องในหน้าสรุป การ์ดยืนยัน อีเมล สัญญา และคิวเช่าของฉัน
4. เมื่อลูกค้าแก้จุดส่งหรือรับคืน ขอราคา Lalamove ใหม่ **เฉพาะขาที่เปลี่ยน** ใช้ snapshot อีกขาตามเดิม หน้าแก้และการ์ดบันทึกการเปลี่ยนแปลงแสดงราคาเก่า ราคาใหม่ และส่วนต่างบวกของขาที่เปลี่ยน หากราคาใหม่ต่ำกว่าหรือเท่าเดิม บันทึกจุดใหม่โดยไม่เพิ่มยอด และไม่แสดงตารางเปรียบเทียบ/ข้อความเรียกเก็บตามข้อกำหนดร้าน
5. กันเก็บเงินซ้ำเมื่อแก้หลายครั้งด้วยราคาฐานสูงสุดที่ลูกค้าถูกเรียกเก็บแล้วของแต่ละขา เช่น 300→380 เพิ่ม 80, 380→350 เพิ่ม 0, 350→400 เพิ่มอีก 20 ไม่ใช้ quote วันนี้แทนราคาเก่าของ Booking เดิมที่ไม่มี snapshot
6. เพิ่มส่วนต่างที่ยืนยันแล้วครั้งเดียวในค่าส่งลูกค้าและยอดรวม Booking คงยอดชำระจริงจาก ledger แยกยอดเพิ่มขาส่ง/รับคืน, จ่ายเพิ่มแล้ว, ยังค้าง, และยอดที่หักค่าประกัน หากขาส่งมีส่วนต่าง ให้เรียกก่อนหรือขณะส่ง; ถ้ายังค้างเมื่อรับคืนจึงหักประกันได้ ขารับคืนที่เพิ่มให้แสดงว่าจะเรียกเก็บหรือหักตอนรับคืน ห้ามเก็บแล้วหักซ้ำ
7. การ์ด “ร้านได้รับเครื่องคืนแล้ว” แสดงค่าประกันที่มีสิทธิ์คืน, ค่าส่งเพิ่มที่ยังค้าง, รายการหักอื่นที่อนุมัติแล้ว และ `ยอดคาดว่าจะคืนหลังตรวจเครื่อง = max(0, ค่าประกันที่คืนได้ − ยอดค้างที่อนุมัติให้หัก)` หากประกันไม่พอ แสดงยอดที่ต้องชำระเพิ่มแยกต่างหาก อย่าเรียกยอดคาดการณ์ว่าโอนคืนแล้ว

## ข้อบังคับเพื่อไม่ให้การเช่าสะดุด

- เพิ่ม payload และ schema รุ่นใหม่แบบ optional ก่อน ผู้ใช้ที่ส่ง–รับคืนที่เดียวกันและข้อมูลเก่ายังคงจอง/ชำระ/ดู Booking ได้ตามปกติ อย่าเปลี่ยนความหมายของ `deliveryFee`, `paidAmount`, `returnTransferRefund` แบบเงียบ ๆ
- ลำดับการเปิดใช้: Backend อ่านเก่า/ใหม่ → Bot รับและคิดราคาใหม่ → เว็บ/Delivery App แสดงข้อมูลใหม่ → เปิด feature flag ให้รายการทดสอบ → ค่อยเปิดเฉพาะรายการใหม่ทั่วไป สามารถปิด flag แล้วย้อนกลับได้โดยไม่ทำให้ Booking ที่สร้างแล้วอ่านไม่ได้
- หาก Lalamove ตอบช้า/ล่ม/หมดอายุ/อยู่นอกพื้นที่ ห้ามใช้ศูนย์แทนราคา รักษาทางเลือก “รอร้านยืนยันค่าส่ง” ของระบบเดิม และห้ามเปิด Beam ด้วยยอดที่ไม่ครบ ลูกค้าต้องเห็นราคาใหม่และยืนยันก่อนชำระ
- Booking เก่าที่ไม่มีราคาต้นฉบับแยกขาให้พนักงานตรวจและกำหนดราคาฐานก่อนคิดส่วนต่างอัตโนมัติ ห้ามคำนวณย้อนหลังจากราคา Lalamove ปัจจุบัน
- ตรวจ Rental ID, รุ่นข้อมูล, พิกัด, quote ทั้งสองขา, ราคา, ส่วนลด, ledger และยอดคงเหลืออีกครั้งก่อนชำระ สร้าง Booking แก้จุด และเรียกรถ หากมีการเปลี่ยนพร้อมกันให้หยุดและให้ยืนยันยอดใหม่
- คำสั่งรถที่เริ่มแล้วห้ามแก้แค่ Booking; ต้องบล็อกหรือให้พนักงานจัดการยกเลิกและเรียกรถใหม่
- เขียน Booking ผ่าน `bookingRepo` เท่านั้น เพิ่ม Sheet schema, PG migration, mapping และ verify ให้ครบ ใช้ revision ID/idempotency key กับทุกการปรับยอด ห้ามสร้าง payment/refund event ปลอม
- `returnTransferRefund` เป็นยอดที่วางแผนจะคืน มิใช่หลักฐานว่าจ่ายคืนจริง แยก ledger คืนเงินจริง และตรวจสรุปงานเช้า–เย็นไม่ให้นับยอดวางแผนเป็นยอดโอนคืนแล้ว

## ตรวจรับก่อนเสนอเปิดใช้

ทดสอบทั้ง TH/EN จากเว็บจอง→Beam/โอน→webhook→Console Pending→Booking→LINE/อีเมล→Delivery App→คิวเช่าของฉัน→แก้จุด→รับคืน→คืนประกัน ครอบคลุมจุดเดียว/คนละจุด, priority ต่างจังหวัด, ราคาเพิ่ม/ลด, แก้ซ้ำ, กดซ้ำ, webhook ซ้ำ, quote ล้มเหลว, จ่ายเต็มแล้ว, Booking เก่า, Bundle/VIP และงานที่เรียกรถแล้ว เทียบ Booking กับ ledger ทีละรายการ ทดสอบการปิด flag และเฝ้าดู quote ล้มเหลว เงินเข้าแต่ไม่มี Booking ยอดไม่ตรง งานรถผิดจุด และข้อความซ้ำก่อนขยายการเปิดใช้

ตัวอย่าง: ขาส่ง 200 + ขารับ 300 − ร้านออก 100 = ลูกค้าจ่ายค่าส่ง 400; เปลี่ยนเฉพาะขารับเป็น 380 → เพิ่ม 80; ค่าประกันที่คืนได้ 2,000 และยังค้าง 80 → คาดว่าจะคืน 1,920 หลังตรวจเครื่อง
